三步快速开始

装好以后，用户不需要懂七层框架。先用 slash command 明确唤起，再说明目标模型和用途即可。

1

输入斜杠菜单

在 Codex Desktop 输入框键入 /image-prompt-architect，从菜单中选择同名命令。

2

给出任务和原始提示词

说清楚是要 GPT Image、Midjourney、FLUX，还是要诊断、迁移、系列图。

3

复制最终提示词

使用输出里的 copy-ready prompt。需要生图时，再要求 Codex 调用图像生成工具。

最短可用写法 
/image-prompt-architect 帮我把这个提示词改成适合 GPT Image 的：美丽女孩，夜晚城市，电影感，大师作品
关键区别：这个 skill 负责把提示词写好，不直接生成图片。想让 Codex 继续生图，就在同一句里补一句“然后调用生图工具生成图片”。

安装和验证

推荐用固定 tag 安装，避免用户装到未发布的开发状态。当前文档使用 v0.14.0。

从 GitHub 安装插件 
codex plugin marketplace add zixuanzhou0-ai/image-prompt-architect --ref v0.14.0
codex plugin add image-prompt-architect@image-prompt-architect
codex plugin list --marketplace image-prompt-architect
只想查看源码 
git clone --branch v0.14.0 https://github.com/zixuanzhou0-ai/image-prompt-architect.git
cd image-prompt-architect
python -m pytest

安装成功后应该看到什么

  • Codex Desktop 输入框键入 /image 后能搜到 image-prompt-architect。
  • 命令详情显示 “Design, rewrite, critique, or port AI image prompt text”。
  • 直接输入 $image-prompt-architect 也能触发 skill。
  • codex plugin list 中能看到插件已安装并启用。

如果斜杠菜单没有出现

  • 先重启 Codex Desktop，或者等待几分钟让 command index 刷新。
  • 试着搜索 /image，不要只搜完整命令。
  • 确认安装的是含 commands 目录和 skill manifest 的版本。
  • 临时使用 $image-prompt-architect 直接调用。

五种使用模式

用户不用手动选择模式，但写请求时越接近下面的说法，skill 越容易输出正确结构。

模式 适合场景 推荐提问 输出重点
quick 只要一个可复制提示词。 “给我一个适合 GPT Image 的 prompt。” copy-ready prompt，外加 2-3 个调参方向。
standard 普通创建、改写、细化。 “把这个模糊提示词改成专业图像提示词。” 结构选择、tagged prompt、最终 prompt、模型说明。
critique 用户已有 prompt，但不知道为什么效果差。 “诊断这个 prompt 为什么很普通，并重写。” 问题分级、缺失控制项、矛盾、改写版。
model-port 从一个模型迁移到另一个模型。 “把这个 Midjourney prompt 改成 FLUX 版本。” 目标模型风险、参数转换、negative 处理、改动说明。
series 多张图、电影感镜头、统一角色或产品。 “做 6 张连续镜头的视觉 bible。” Identity lock、continuity、variation budget、shot slots。

不同模型怎么写

把目标模型说出来，skill 会自动切换提示词形状和禁用项策略。

GPT Image

  • 用自然语言描述清楚主体、环境、光线、构图和约束。
  • 编辑任务要写清 preserve / change / replace only。
  • 需要文字时把准确文案放进引号。

Midjourney

  • 参数放在最后，例如 --ar 4:3 --stylize 80。
  • 排除项用 --no，不要写 Stable Diffusion 风格的 Negative Prompt。
  • 避免把长解释和参数混在一起。

FLUX

  • 尽量用正向替代表达，不写 no crowds 这类否定句。
  • 品牌色、材质、产品结构要具体。
  • API 使用时区分 prompt 内容和 request wrapper。

Grok Imagine

  • 说清参考图控制身份、风格、构图还是色彩。
  • 数量、比例、分辨率等设置不要伪装成视觉提示词。
  • 视频和编辑任务要单独说明动作或改动范围。

Dreamina / Seedream

  • 中文或中英混合都可以，重点是视觉细节和审美锚点。
  • 不要把模型报告等同于具体 UI 的最佳实践。
  • 适合写成 “主体 + 场景 + 美学关键词” 的清晰组合。

Stable Diffusion wrapper

  • 只有界面支持时才保留 positive / negative 双字段。
  • 不要把 SD 的 negative block 直接搬到 FLUX 或 Midjourney。
  • 采样器、seed、LoRA、control 等参数要和 prompt 分开。

美丽女孩，夜晚城市，电影感，大师作品

改写方向

一位 24 岁东亚女性站在雨后的城市人行道边，深色羊毛外套，微湿发丝被霓虹招牌映出青绿色轮廓光，远处出租车灯光拉成长焦散景，35mm 街头电影剧照，低角度半身构图，潮湿柏油路反射粉红与琥珀色光，安静、克制、略带悬疑的夜晚氛围。

推荐工作流

把 skill 当成提示词架构师，而不是一次性万能 prompt 生成器。最稳的流程是先定目标，再迭代。

先说目标

说明要给哪个模型用、是单图还是系列、是否要文字、是否要参考图、是否要继续生图。

再要结构

需要精细控制时说“用七层结构”；需要多图一致性时说“做 series bible”。

最后迭代

如果出图不对，把失败现象贴回来，让 skill 根据失败点写 revision prompt。

不要这样用：“帮我生成一张图片。”这会绕过 skill 的价值。应该写：“用 /image-prompt-architect 先把这句话改成 GPT Image 提示词，然后生图。”

常见问题

这些问题来自真实安装和测试过程中最容易卡住的地方。

别人能一键安装吗？

当前是 Codex plugin marketplace 风格安装：两行命令完成安装。它不是网页按钮意义上的一键，但对 Codex CLI 用户已经足够可复制。

  • codex plugin marketplace add 添加仓库源。
  • codex plugin add 安装插件。

为什么有 `/` 和 `$` 两种调用？

/image-prompt-architect 是斜杠菜单命令，适合桌面端用户；$image-prompt-architect 是直接 skill mention，适合命令没刷新时兜底。

为什么 skill 不直接生图？

它的职责是写好提示词、适配模型、诊断问题。生图需要另一个图像生成工具。可以在同一句里要求 Codex “然后调用生图工具生成图片”。

斜杠菜单搜不到怎么办？

先确认插件已安装，再重启 Codex Desktop。菜单有缓存时，等几分钟或新开会话再试。仍不行就使用 $image-prompt-architect。
